¿Qué es y para qué sirve?

Este conector permite al agente de Ruvic leer secretos gestionados en AWS Secrets Manager: obtener el valor de un secreto, listar los secretos disponibles (solo metadatos), y opcionalmente disparar una rotación.

Este conector puede exponer valores reales get_secret devuelve el valor real del secreto en texto plano. Restringí el alcance al mínimo indispensable con el prefijo de nombre.
OperaciónQué hace
secrets.get_secretObtiene el valor de un secreto
secrets.list_secretsLista los secretos disponibles (metadatos, no valores)
secrets.rotate_secretDispara una rotación inmediata (opcional)

Prerrequisitos

  • Al menos un secreto ya creado en AWS Secrets Manager.
  • Acceso a la consola de AWS IAM para crear un usuario dedicado.

Configuración en el fabricante

  1. Organizá tus secretos con un prefijo dedicado.

    Si podés, nombrá los secretos que Ruvic va a leer con un prefijo común (ej. "ruvic/") para poder restringir el acceso fácilmente.

  2. Crea un usuario IAM dedicado.

    En IAM → Usuarios → Crear usuario. Solo acceso programático.

  3. Adjuntá una policy restringida por prefijo. 
    {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["secretsmanager:GetSecretValue", "secretsmanager:ListSecrets"],
      "Resource": "arn:aws:secretsmanager:*:*:secret:ruvic/*"
    }
  ]
}
  4. Genera las claves de acceso.

    Guardá el Access Key ID y el Secret Access Key — el secreto solo se muestra una vez.

Permisos requeridos

PermisoPara qué sirve
secretsmanager:GetSecretValueObtener el valor de un secreto (get_secret)
secretsmanager:ListSecretsListar secretos (list_secrets, test de conexión)
secretsmanager:RotateSecretDisparar rotación (rotate_secret, opcional)
Nota Restringí el Resource por prefijo de ARN/nombre — este conector puede exponer valores reales, así que el alcance debe ser el mínimo indispensable. No se otorgan permisos de administración (CreateSecret, DeleteSecret, PutSecretValue).

Configuración en Ruvic

Entrá a Settings → Conectores, buscá AWS Secrets Manager y pulsá Configurar. Completá el Access Key ID, Secret Access Key, Región, y opcionalmente el prefijo permitido (ej. "ruvic/").

Probar conexión — la plataforma listará secretos (solo metadatos) para confirmar credenciales.

Verificación

  1. Test de conexión exitoso.

    "Probar conexión" debe responder con éxito.

  2. Prueba mínima con el agente.

    Pedile:

    "Listame los secretos disponibles (solo nombres, no valores)."

    El agente debe devolver el listado real de nombres de secretos.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Credenciales inválidas o sin permiso IAM suficiente"Access Key inválida/rotada, o la policy no incluye el permiso ni el prefijo de Resource necesario.
"El secreto no existe o no es accesible"Nombre mal escrito, región incorrecta, o el secreto no coincide con el prefijo permitido configurado.
"El secreto no coincide con el prefijo permitido"Configuraste RUVIC_SECRETS_MANAGER_SECRET_NAME_PREFIX y el nombre pedido no empieza con ese prefijo — es intencional, una capa extra de seguridad.
Error al rotar: "no tiene rotación configurada"El secreto necesita tener una función Lambda de rotación configurada en AWS antes de poder dispararla desde acá.
El conector aparece "Sin configurar" tras guardarAlgún campo obligatorio quedó vacío. Completá Access Key ID, Secret Access Key y Región.

Preguntas frecuentes y notas de seguridad

¿El agente puede leer cualquier secreto de mi cuenta?

Solo los que permita la policy IAM, y si configuraste un prefijo de nombre, solo esos — es una doble restricción (IAM + código).

¿Dónde queda guardado el Secret Access Key?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlo.

Rotación de credenciales del propio conector

Recomendado cada 90 días: generá un Access Key nuevo en IAM y actualizalo en el formulario (no confundir con rotate_secret, que rota los secretos que el conector consulta).

¿Qué hago si las claves se comprometen?

  1. Desactivá el Access Key inmediatamente en IAM.
  2. Revisá CloudTrail por accesos GetSecretValue inesperados.
  3. Considerá rotar los secretos que pudo haber leído el conector.
Buenas prácticas Configurá siempre el prefijo de nombre permitido; nunca des acceso a todos los secretos de la cuenta; y evitá mostrarle al usuario el valor de un secreto salvo que lo pida explícitamente sabiendo que lo va a ver en texto plano.
